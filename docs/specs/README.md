# Specs

This directory stores approved implementation contracts.

A substantial feature should not reach implementation while material product/design/architecture decisions are still unresolved.

Typical flow:

1. Run the project intent gate.
2. Grill unresolved decisions.
3. Confirm shared understanding.
4. Write the spec.
5. Implement against the spec.
6. Review the result on both Standards and Spec axes.

Specs should describe durable intent and decisions, not fragile line-by-line implementation instructions.
